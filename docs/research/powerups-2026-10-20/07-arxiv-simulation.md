# 07 - arXiv simulation wave (2026-10-20)

## Answer

The engine already owns the *authority* bodies: an integer Q16 ragdoll with a joint table
(`crates/physics/src/ragdoll.rs`, `crates/physics/src/joint_limits.rs`), a float Rapier
presentation layer that is never hashed (`crates/physfx/src/fx.rs`), a Verlet cape cloth
(`crates/physics/src/cloth.rs`), a two-bone IK + foot-lock chain (`crates/anim/src/ik.rs`,
`crates/anim/src/feet.rs`), an additive pose layer (`crates/anim/src/layers.rs`,
`crates/anim/src/hit_react.rs`, `crates/anim/src/inertialize.rs`), a per-fighter physics
tracker (`crates/anim/src/net_pose.rs`, `crates/anim/src/motion_match.rs`) and a
snapshot/rollback fork harness (`crates/arena/src/fork.rs`, `crates/physics/src/islands.rs`,
`crates/proof/src/ragdoll_matrix.rs`). So the arXiv papers that move it are not "another
solver" and not "another DeepMimic": they are the **missing control shapes that turn our
existing integer bodies into people** - a keyframe-free get-up controller, a per-joint
force/friction/damping table, a rotation-equivariant additive flinch layer, a CPU
retargeter that keeps the foot planted, and two determinism papers that say exactly how
the job pool and the physics oracle must be written so the golden hash survives 1 vs 8
workers and Windows vs wasm. Twelve rows, ranked by how much of the "bodies move like
people" gap they close for the least engine work.

Method note: the arXiv **export API rate-limited (HTTP 429) on the first query and then
kept refusing**, so every entry below was read from the `arxiv.org/abs/<id>` page
(webfetch, HTTP 200) and the version and date come from the live `Submission history`
block on that page. GitHub facts (code URL, license file text) were read live with the
GitHub MCP on 2026-10-21; where a repository exists but ships no LICENSE file the license
is written **UNVERIFIED** and the row says "do not vendor bytes". Evidence grades follow
`RULES.md`: OBSERVED = read today on the named page; DERIVED = reasoned from what was
read; INFERRED = likely, not proven; UNKNOWN = not measured.

Rows already closed before this wave and therefore **not** re-proposed here: PX10 (CCD,
archived), PX16 (1,000-agent LOD, landed 0494dbd3), PX17 (64-fighter snapshot, landed),
PX23-PX29 (archived D-RAGDOLL-1 / D-CLOTH-1 tapes, cloth coupling, folded-curtain self
collision), DX13 (destruction snapshot + resim, archived), LF15 (FLIP metric, landed
061667e3), RZ1-RZ9 (physfx layer, ragdoll on knockout, limbs off, blast, cloth, material
table, budget ladder - all landed). LF14 (weapon trails) is a GPU strip draw with no arXiv
donor that would not break the hash, so it gets no row.

## Top 3

1. **arXiv 2304.05056 "Real-Time Character Rise Motions"** (v1, 2023-04-11) - https://arxiv.org/abs/2304.05056 - closes **RZ2** (get-up clip) and feeds **BX5**. A keyframe-free get-up controller is the single missing shape between "fighter ragdolls" and "fighter stands up like a person"; it ports as integer targets plus priority IK, no donor bytes, no float in the tick.

An additive, rotation-equivariant motion layer on the real skeleton is the fix for `hit_react.rs` writing identity rotations and for the 8-fighter pop count.
3. **arXiv 2607.02529 "RepliCore: Reproducible Parallel Simulation under Asynchronous Browser Runtimes"** (v2, 2026-07-15) - https://arxiv.org/abs/2607.02529 - closes **E21** (job pool, golden equal at 1 and 8 workers) and backs **C15** (physics oracle on Windows and wasm). A logical-state visibility barrier is the cheapest way to make the golden hash survive parallelism and the browser.
