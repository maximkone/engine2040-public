## Answer

The chain is half built and the middle is cut. The brief side is real: the door already speaks
`scene.brief` and the four build verbs, `level.build` (crates/endpoint/src/tools.rs:58),
`character.build` (crates/endpoint/src/build_character.rs:30), `sim.build_encounter`
(crates/endpoint/src/build_encounter.rs:24) and `game.build` (crates/endpoint/src/tools.rs:130),
and the stage enum names the pillar exactly (crates/endpoint/src/brief.rs: `BriefStage` =
Level, Character, Encounter, Slice, Replay). The cook side is real too: `asset.intake` cooks a
generated GLB to a prop with a licence gate, 5,000 triangles, LOD, hull, bundle, provenance row
and a cache (crates/endpoint/src/packs/asset/intake_verb.rs), and crates/assets/src/gen_intake.rs:589
already is a content-addressed cache. What is missing is the middle: nothing starts a generation
job. `asset.generate` is a text explainer that prints `node kaggle.mjs run mesh ...` with
`runs_here: false` (crates/endpoint/src/packs/asset.rs:45), and that file does not exist. There is
no `kaggle.mjs` in `C:\empire\center` today and none in git history; the board says so itself
(docs/SPRINT-10-empire-inbox-drain.md:232: "target `kaggle.mjs` (center mesh step) is gone; the
center pipeline was retired"). So rows GN4, GN5, GN7 and GN8 all name a file that is not there:
they need a new home before any of them can start. Two more holes sit under the words: the
licence gate trusts the caller's SPDX string instead of the model card, and `engine2040 run`
plays the default arena proof while ignoring the project's own `game.toml` content, so the
one-call promise (gap C12) is a promise about a manifest, not about a game. The city side has no
generator at all: crates/world/src/city.rs does not exist. The Rome district itself is written by
hand and looks close to done (four cells, a traversal route with vault, mantle and climb, an AI
chase on nav links, CC0 provenance), but nothing can make a second district, and nothing imports a
real map. The hard rule from D3 holds and must hold: generation is an editor job, the shipped game never
generates, only free commercial-use models, and every generated byte must pass the provenance
gate and cook identical twice.

## Procedural generation, PCG and LLM level makers: the short read

- Wave function collapse: already in the tree (crates/world/src/wfc.rs, mxgmn and krychu shapes,
  MIT, ideas only). WD14 is a different solver: node restrictions and a backtrack cap (row 9).
- City grammar: nothing in the tree, the donor repo is gone (row 7).
- Learned PCG (PCGML): the survey is arXiv 1702.00539, and the cleanest reference repo is
  Mawiszus/TOAD-GAN (MIT, read 2026-10-20). We do not need it: a GAN level is neither integer
  deterministic nor seedable x2, and our bakes must be. Verdict: RESEARCH-ONLY, do not port.
- LLM-driven level generation: Holodeck (Apache-2.0, read live 2026-10-20) and LayoutVLM
  (arXiv 2412.02193) are already mined and already partly in the tree: the door has `level.build`
  and a brief stage, so the missing piece is not the prompt parser, it is the generator that turns
  a solved brief into cells. Inverse procedural design: no licence-clean repo found today,
  UNKNOWN, so no row.
- LLM-driven materials: T2MAT (arXiv 2407.06489) and Chord (arXiv 2509.09952) are ideas only;
  the port target is our own bake (row 4, FU6).
- LLM-driven shaders: ShadAR (arXiv 2602.17481) and AI Co-Artist (arXiv 2512.08951) are ideas
  only; the port target is our own WGSL generator behind the door, gated by a compile test and
  never inside the tick.
