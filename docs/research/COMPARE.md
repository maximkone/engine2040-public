## Comparison rubric R-CMP-2

Freeze 5-12 capability items per row from at least two primary source families.
All engines use the same items, weights, versioned fixture and applicability rules.
Record built-in, optional first-party, third-party and external-tool support separately.
An excluded item needs a published reason applying equally to every engine in that comparison.

- **Coverage %:** complete passing capabilities / fixed applicable capabilities.
  Record documented coverage separately from locally tested coverage. Docs are
  evidence of a publisher's capability claim, not performance or our test passing.
- **Power %:** publish per-item acceptance depth and weights first; sum attained
  depth (0 absent, 0.5 explicitly partial, 1 the full criterion) / total weights.
  The depth scale uses outcomes such as load-path collapse plus rollback, not prose
  adjectives. Unmeasured depth stays UNKNOWN; no guessed half-credit.
- **Performance:** report latency/frame time/VRAM/scale on the same fixture and
  hardware, separately. A feature checklist cannot substitute for a GPU or WAN run.
- **Unknowns:** retain them in the fixed denominator. With missing evidence report
  `confirmed n/N; unknown u/N` and, if useful, a labeled lower/upper bound. Never
  divide only by known items, turn missing evidence into FAIL/zero, or report a
  completed percentage from a partial sample. Overall remains UNKNOWN.
- **Evidence:** each item has PASS, PARTIAL, FAIL, DOCS-CLAIM or UNKNOWN; source
  URL and revision/version, date, scope, consumer, test/capture and its result.
  Source code alone is not integration. Proprietary binaries can earn measured
  proof when run locally; public docs alone cannot. A paper's benchmark is the
  author's result and never our runtime result.
