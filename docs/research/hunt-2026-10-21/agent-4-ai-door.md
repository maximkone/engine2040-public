## 0. What our tree already has (so the table does not propose it twice)

- `crates/endpoint/src/resources.rs` (20 KB) and `crates/endpoint/src/scenarios.rs`
  (10 KB) exist but are **untracked**; `crates/endpoint/src/mcp.rs` is modified
  (+145 lines) and already wires `list_resources` / `list_resource_templates` /
  `read_resource`, the five scenario prompts, and a `send_progress` helper
  (progress 0.0 at the start, 1.0 at the end). **D16 is in flight in this
  tree right now** — a second session must not land the same row. The donors
  in rows 6 and 12 of the table refine that work; they do not start it.

  text. `crates/endpoint/src/packs/sweep.rs` (13 KB) ships `play.sweep`: seeded
  bots play N headless bouts and answer one envelope (crashes, hash

  "one knob, a range, 5 seeds, a CSV and the win-rate curve". The knob sweep
  with the curve CSV exists — `sweep_difficulty_curve` and `render_sweep_csv`

  `crates/endpoint/src/packs/physics_settings.rs` ships `settings.get` /
  `settings.set` / `settings.undo` over a knob table with legal ranges, and
  `settings.undo` writes the previous state back at a later tick so the tape
  stays replayable. So D20 needs: the test-gated curve promoted to a
  production function, a `tune.sweep` verb over it, 5 fixed seeds, and the
  landing as one `settings.set` + `settings.undo` pair.

  (one tick per press, `paused tick=<N>` receipt line) and a slow-mo key.
  C13's missing half is cvars, a console, and a tick-phase profiler.

  answers; `crates/provider/src/pins.rs` pins temperature 0 and a seed.
- `crates/playtest/src/mirror.rs` + `tasks.rs`: the 30-task mirror with
  `UNKNOWN` cells for rivals we did not run. **No pass@k / Play@k anywhere**
  (`rg "play_at_k|pass_at_k|play@k"` over `crates/` = 0 hits).

### Gap found in our own tree (no donor needed) — D20 `tune.sweep` is half-built

D20 reads as done because `crates/endpoint/src/packs/sweep.rs` ships
`play.sweep`, but that verb is a **crash / drift / freeze** sweep over N seeded
bouts, not D20's "one knob, a range, 5 seeds, a CSV and the win-rate curve".
The knob sweep with the curve CSV already exists in our tree but is
**`#[cfg(test)]`-gated**: `sweep_difficulty_curve` and `render_sweep_csv` at
`crates/playtest/src/tournament.rs:1602-1665`, with `SWEEP_KNOB`,
`SWEEP_VALUES`, `SweepConfig` and `SweepReport` all test-only, emitting
`knob,value,difficulty,player,win_rate_permille,kill_shares,stuck_count,trials`

(`rg "tune\.|tune_sweep"` over `crates/endpoint` = 0 hits). The undoable

tick so the tape stays replayable. The work: promote the curve out of the test
module, add a `tune.sweep` verb over it taking one knob name, a range and a
seed count (5 fixed seeds), return the curve rows plus the CSV bytes, and land
the chosen value as one `settings.set` + `settings.undo` pair. Size S. Risks:
the knob today is fight length (`match_ticks`) and D20 says "one knob", so the
verb must name any knob in the `settings.get` table; the sweep must not read
a clock or an unseeded RNG, or the "same seed, same curve" promise the
`fix-a-red-capture` / `tune-a-hit` scenario prompt already makes breaks. Kill:
two runs of the same seed giving two different curves.

## 2. Wild ideas (techniques no GitHub engine has for AI-native work)
1. **The verdict that cannot be forged.** Take row 3 to its end: our door's `verdict: "pass"` becomes a `Certified` variant with no public constructor, minted only by a `CheckerRun` that actually ran and read an exit status, carrying the digest of the inputs it was handed, non-`Copy`, with `is_about(artefact)` so a holder can ask whether the token is about the thing in its hand. Then the door physically cannot print "pass" for an edit nobody checked. No engine on GitHub makes its own success word un-printable.
2. **The mutant contract.** Every programmatic referee we ship must have a **mutant**: a build that differs by exactly one deliberate break and must fail **exactly** one named predicate. A referee that cannot fail is not a referee. We would be the first engine whose build suite can prove its own graders discriminate. Cheap: 4 tasks, 4 mutants to start.
3. **The referee the agent cannot read.** Row 2's `SEPARATE` verifier mode. Our build tasks would score against a referee that lives behind a boundary the agent's tools cannot reach: the agent gets a verdict, never the grader. Combined with row 3, the agent can neither read nor forge the grade.
4. **Project memory keyed by tape hash.** Row 5's format, keyed by OUR tape digest: every decision, failed fix and tuned value is a Markdown record whose front matter carries the FNV-1a tape hash of the run that produced it, whose `evidence` refs pin the exact bytes (digest + length) of the artefact, and whose status moves `proposed → current → superseded` by moving the file, never by editing the body. The door serves it as a resource family plus an always-loaded brief under 8 KB. An agent that asks "why is this number 42?" gets a file, a tape hash and a byte-pinned evidence pointer.
5. **The differential ship check.** Row 4 on Windows: a curated scenario list runs against the reference build and the candidate build, and every step of the receipt is diffed with a normalization list. Exit 1 on one in-scope divergence. That is E22 with teeth: not "the build ran" but "the build behaved the same as the last good build, except where we said it may".
6. **The agent plays through the human verbs.** Our `input.inject` and `play.step_until` mean an agent can drive the same fight a human drives. Push it: an agent's bout is recorded in the SAME tape format as a human's bout, so the playtest suite can score agent and human play with one referee, and the agent scorecard (AG1) reports against a human baseline rather than a rival engine's published number.
7. **The window is the door.** Expose the in-game console (row 11) over the same door, so an agent debugging the running game types `cvar d_draw_lines 1` and reads the frame, and a human types the same thing in the same window. One debug surface, two users, one truth — and the agent's console session is a receipt, not a screenshot.
8. **The receipt is the verifier.** Row 1 + D19: a build verb's reply IS its verifier output (the predicate table's rows, the first failing predicate and its severity, the evidence digests), so "the build passed" and "the build's evidence" are the same bytes. CI compares receipts; an agent reads receipts; nothing needs a second report format.
9. **A metric whose number cannot be gamed.** Row 3's `closure_diff.rs` lesson: our win-rate and look scores are ratios, and a ratio has an optimisation direction that a lazy tuner can exploit (raise the denominator). We should print the **count** beside the ratio ("N of M runs ended in a stuck tick") and say in the payload which way the number is easy to move.
10. **A door lockfile as a release.** Row 9 taken seriously: the door's tool surface becomes a versioned artefact with a semver classification of every change, and the door's own `version` is what an agent pins. An agent that upgrades the engine and reads a breaking change before it breaks is a new class of safety no game engine offers.
11. **The knob is the verb, not the argument.** The D20 discovery above generalises: our door already has typed knobs with legal ranges (`settings.get` prints name, unit, range and value; a bad number refuses and names the range). Make **every** tuning surface speak that language — the sweep, the balance editor, the AI curve draft — so an agent never learns two dialects of "change this number". The first engine whose whole tuning surface is one typed table that a machine can read.

## 3. Rejected (checked, and why they lose)

- **modelcontextprotocol/** (rust-sdk, python-sdk, servers, registry, conformance) — already mined; also our lock already ships rmcp 3.4.1, which has `notify_progress`, `list_resources`, `read_resource`, `TaskManager` and `CallToolResponse::Task`. Nothing to port that is not already a dependency.
- **mem0ai/mem0** — already mined. Beyond that: a vector-DB memory is the wrong shape for a deterministic engine. Our memory must be byte-reproducible and keyed by a tape hash; a similarity index cannot answer "which run produced this".
- **UKGovernmentBEIS/inspect_ai** — already mined. An LLM-judged harness is the opposite of D18's "programmatic referees, no LLM judge".
- **EricLBuehler/mistral.rs** (7761★, MIT) — read `mistralrs-core/src/kv_cache/*` and `prefix_cacher.rs` and rejected: we do not run our own inference. `crates/provider/src/local.rs` talks to a `llama-server` sidecar and `arbiter.rs` already places it on GPU/CPU/Defer/Remote. KV eviction and prefix caching are the sidecar's business; a 229 MB inference stack is not a surgical steal. (Its `mistralrs-core/src/paged_attention/kv_cache_manager.rs` would be the file to read **if** we ever owned the inference.)
- **gastownhall/beads** (the Go binary, not the harness) — the product is a Go issue tracker; only the Rust oracle harness (row 4) is a donor. The scenarios are `bd` CLI shaped and would have to be rewritten entirely for our receipt format.
- **Aureliolo/gdharness** (25★, MIT) — read `docs/agent.md`: the "Refuse" list is excellent ("refuse to report provenance as verified when no check ran", "refuse to start a second editor on a project that already has one") and the install/diagnose CLI is the right shape for C12's `new`. But the substance is GDScript editor addons plus a Godot runtime autoload, and Godot is not our engine. Ideas only, no file to port.
- **nextest-rs/nextest** (3353★, Apache-2.0) — a test runner, not a door. Our tests run through `tools/gh-check.mjs` on GitHub runners already; a second runner changes nothing on the door path.
- **wgt19861219/godot-mcp-enhanced** (100★, NOASSERTION) — read `.claude/skills/screenshot-verify/SKILL.md` and the verify-loop skill. Two good rules: always capture a BEFORE screenshot so a diff has a baseline, and headless blank frames are a known limitation, not a bug. But the license is NOASSERTION, so ideas only, and 1593 blobs of GDScript is a framework, not a steal.
- **EleutherAI/lm-evaluation-harness** (14279★, MIT) — read `lm_eval/api/samplers.py`: the seeded `Random(rnd)` few-shot sampler is a good determinism idea but we already pin temperature 0 and a seed in `crates/provider/src/pins.rs`. The harness is Python and its task model is a doc/question pair, not a build that has to compile and play. It loses to row 1, which is the same idea in the shape we need.
- **EverMind-AI/EverOS**, **topoteretes/cognee**, **vectorize-io/hindsight**, **letta-ai/letta** — all found in the "agent memory" search and all rejected: they are memory **platforms** with databases and embeddings. We need a file format and a hash chain (row 5), not a service.
- **makepad/makepad** `libs/ai/services/src/mcp/server.rs` (7204★, MIT) — a full HTTP MCP server with bearer tokens; we run stdio and already have CAP1. Its loopback route table is 48 KB of transport work we do not need.
- **tugcantopaloglu/godot-mcp** (157 tools), **Coding-Solo/godot-mcp**, **Roblox/studio-rust-mcp-server** — verb-count arms races. Our door is typed, priced and capped; 157 verbs is the opposite of the design.
- **tenuo-ai/tenuo** (101★, Apache-2.0) — cryptographic warrants for tool scoping. HS21 (capability scopes and auth) is real, but our CAP1 approval already binds session, revision, action and expiry, and tenuo's own README says it is a full auth platform. Overkill for the next row.
- **xerj-org/xerj**'s WAL tap (`engine/crates/xerj-api/src/wal_tap_api.rs`) — read and rejected: it streams one node's whole index to another host with a bearer credential. Our audit log already rotates a window and advances an anchor digest; the remote-tap half is not our problem.

## 4. One-line verdict

**SummerEngine/summer's `evals/outcomes` is the best steal in this domain** — its
predicate table with declared evidence sources and ordered severities, plus its
**mutant rule** (a broken build must fail exactly one named predicate) and its
"unevaluable is FAIL, never a skip" honesty rule, are the only things anyone
else on GitHub has written for D18/D19, and they give us both the 10-task
programmatic referee suite and the proof that our graders actually grade.
