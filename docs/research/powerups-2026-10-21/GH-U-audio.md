# GH-U — procedural and adaptive game audio: donor repos

Lane: GH-U (research only, one file). Read date for every donor below: **2026-10-21**.
Rules: `docs/research/powerups-2026-10-20/RULES.md`. Row id prefix: GH-U.

## Answer (one paragraph)

The best donor for a hit that sounds like a hit is **Chirrp** (`steven-moss-notebook/Chirrp`, MIT OR Apache-2.0): it already ships, in Rust and with no sample files, a per-material physical model (`src/surface.rs`) where the contact force is `velocity × load`, each surface gets its own modal resonators (wood board, metal grate, gravel grains, mud, snow, water), and the footstep is a heel-strike → weight-transfer → friction sequence; the same crate also carries `SoundKind::Impact`, `MeleeHit`, `Whoosh`, `Swing` and `Footstep` recipes. Two more donors give the missing halves: **oaml** (`oamldev/oaml`, MIT) is an adaptive-music library whose music tracks are chosen by *named conditions* set from game state (a tension condition id), which is exactly the seam our `crates/audio/src/director.rs` intensity curve does not have (it knows fight intensity, not war state); and **GoogleChromeLabs/web-audio-samples** (Apache-2.0) ships the *free-queue* pattern, a lock-free single-producer/single-consumer ring between the page and the `AudioWorklet`, which is the cheapest way for our mix to keep running when the tab is hidden and the page timers are throttled. Behind them sit **rsfxr** (Apache-2.0) and **ZzFX** (MIT) for "one parameter set → one sound" (swing whoosh, blade ring) and **Yasuno-5555/DirtyData** (MIT) plus **SamiPerttu/fundsp** (MIT OR Apache-2.0) for the modal-resonator and biquad-bank shapes. The richest *algorithms* (impact-from-force, terrain footstep, speed-driven whoosh) live in **MacCracken/garjan**, which is GPL-3.0-only: read it, write our own Rust, never copy a line. No proprietary donor is needed for anything proposed here.

## What our tree already has (rule 6: checked before calling anything a gap)

All OBSERVED on 2026-10-21 by reading the files in `C:\engine2040`.

- `crates/audio/src/bank.rs:91` `Bank::synth(kind, sample_rate, variant)` bakes 11 fixed voices. `bake_hit` (`bank.rs:110`) is a 180 Hz thump + 5 ms click through a resonant body; the only variation is `variant` (a small integer offset: `+14 Hz` per variant). There is **no material input and no force input** — OBSERVED.
- `crates/audio/src/combat_cues.rs:61` `cue_for_event`: `FightCue::Hit` → `names::HIT` with a fixed `gain: 1.0`; `Blocked`/`Parried`/`Dodged`/`Knockdown` are other fixed names and fixed gains — OBSERVED. `footstep(surface)` (`combat_cues.rs:97`) is one cue name per surface with fixed `gain: 0.8` — OBSERVED.
- `crates/audio/src/strike_sound.rs:190` `CueRow { name, gain }` with `SEVER_TABLE`, `LANDING_TABLE`, `GROAN_TABLE`, `COLLAPSE_TABLE` (`strike_sound.rs:515-542`): a lookup table of (clip, fixed gain), no synthesis and no force term — OBSERVED.
- `crates/physics/src/material.rs:184` `Material::cue(impact_speed_mm_s) -> Cue { class, loudness }` already names the sound family of a material and buckets loudness at `LOUDNESS_STEPS_MM_S = [400, 1_500, 4_000]` mm/s (`material.rs:78`) — OBSERVED. **But nothing in `crates/audio` reads `SoundClass`** (`git grep SoundClass -- crates/` hits only `crates/physics/`), and `crates/audio` does not depend on `engine-physics` — OBSERVED. The seam is open: physics knows material + speed, the audio crate never sees them.
- `crates/audio/src/music.rs` is seeded adaptive music: 4 layers, `LAYER_THRESH = [0.0, 0.3, 0.55, 0.8]` (`music.rs:22`), a `Tension` enum with hysteresis (`music.rs:259-272`), a 16-step bar grid and a beat bus — OBSERVED. `crates/audio/src/director.rs:389` `Director::update` turns fight events into an intensity and asks the music player for layers, with a `restraint_no_hard_cuts` rule (`director.rs:618`) — OBSERVED. So **intensity-driven layering exists; a war-state condition system does not** (no board row mentions music: `grep "music" docs/SPRINT-*.md` over row lines returns nothing).
- `crates/audio/src/heal.rs` holds the last frame over XRUN gaps (board row SN11, landed) — OBSERVED.

So the gaps this lane can feed are: (a) sound that varies with **material and force**, (b) **procedural** footsteps and swings instead of clip lookups, (c) a **war-state condition** layer on top of the existing intensity director, (d) a mix that survives a **hidden browser tab**.
