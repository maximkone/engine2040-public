# GH-A — animation game feel: donors for hit reactions, impact frames, anticipation and follow-through, squash-and-stretch, pose blending, foot IK

Lane question: which open-source GitHub repos hold production-grade techniques for the animation half of a 2005-MMO combat feel (commitment, weight, readable telegraphs, a hit that lands) that our tree can port — hit reactions with weight, impact frames, anticipation and follow-through, squash-and-stretch, pose blending, foot IK and ground snapping? Written 2026-10-21; every donor file and LICENSE below was read live today through the GitHub contents API or `gh api`. Nothing is vendored: every port is our own Rust, view-side and integer where the tree allows it.

**Answer.** Our tree already owns the machinery: motion matching (`crates/anim/src/motion_match.rs`), an integer IDW blend space (`crates/anim/src/space.rs:19-21`), an ordered masked layer stack (`crates/anim/src/layers.rs:215-281`), a spring chain (`crates/anim/src/springs.rs`, `crates/anim/src/inertial.rs`), two-bone IK with a foot lock (`crates/anim/src/ik.rs:192` `two_bone`, `:446` `foot_lock`; `crates/anim/src/feet.rs:73` `solve_two_bone`), a crossfade (`crates/anim/src/crossfade.rs:22`) and a C1 clip sampler (`crates/anim/src/pose.rs:16-27`). What it does **not** own is the three things this lane is about. First, **a swing that shows its windup**: the press cue exists in combat (`crates/combat/src/fight.rs:463` `AttackStarted`) and is copied into the game crate (`crates/game/src/lib.rs:1409-1411`), but the fighter look never receives it — `fold_cues` starts the swing only on outcome cues (`crates/game/src/fighter_look_acts.rs:268-303`) and back-dates it by `IMPACT_TICKS = 12` (`crates/game/src/fighter_look.rs:2168`), so zero ticks of windup show (OBSERVED). The named clip markers that would fix that are the single strongest find here: `playcanvas/engine` sorts clip events by time and walks them with a cursor (`src/framework/anim/evaluator/anim-events.js`, `anim-clip.js`), which is exactly what row **GP44** already asks for ("windup-peak and impact markers in the clip event track", `docs/SPRINT-21-look-feel.md:333-341`). Second, **a hit that lands**: the flinch writes positions only and leaves every rotation at identity (`crates/anim/src/hit_react.rs:261-278`, `:276`), and its envelope is a linear ramp to zero over 6 ticks (`crates/anim/src/hit_react.rs:228-234`, `crates/combat/src/fight.rs:67`), while the plan asks for a ~450 ms view envelope with in, hold and out (`docs/plan/animation.md:184`). The rotation lane itself is **PW32**'s, so this lane adds the *punch* (a short out-and-back with a decaying vibrato) from `mixandjam/Balatro-Feel` as a fifth impact-fan-out layer under **GP22**. Third, **any overshoot curve at all**: the tree's fade set is four fixed curves with no overshoot (`crates/anim/src/state_machine.rs:116-125`), so anticipation and follow-through cannot be expressed; the portable donor for that is one polynomial, `d3/d3-ease` `src/back.js`, because our sampler law allows only `+ - * /`, `%` and `sqrt` (`crates/anim/src/pose.rs:29-31`) and `d3-ease`'s elastic file would break it with `Math.asin`. Two more gaps are real but owned elsewhere: the tree has **no scale lane at all** (no scale in `Pose`/`LocalPose`, none in `skinning_matrices`, none in the clip format, and the importer rejects scale channels), so squash-and-stretch cannot be expressed in the pose at all; and the **foot IK has no ground** (`crates/anim/src/feet.rs:89-98` clamps to a flat plane, no normal anywhere in `crates/anim`), which is **LM6**'s job.
