# GH-K — stylised low-poly character pipeline: the techniques we are still missing

Lane question: which open-source GitHub repos hold techniques and tools for a STYLISED LOW-POLY CHARACTER PIPELINE (real anatomy as a game base, caricature proportions, armour plates fitted and weighted to a rig, painted mask faces, painted vertex-colour light, toon/prop authoring, low-poly weapons that read at 30 m)?

**Answer.** The anatomy, the caricature bands and the painted-light layer are already ours (`tools/blender/mpfb_body.py`, `tools/blender/proportion_pass.py` + `content/design/proportions.json`, `tools/blender/style_cook.py` `LIGHT` layer). Four real gaps remain, and each has a permissive donor: (1) **the armour pass does not shrinkwrap** — `content/design/asset-pipeline.md:182-185` records "armour by shrinkwrap" as the standard way, but `git grep -in "shrinkwrap" -- tools/ crates/` returns **0 hits**; `tools/blender/armour_pass.py:246-261` measures a local limb radius and scales a template, and `transfer_weights` (`:117-148`) copies the **nearest body vertex's** weights, so every plate edge is a hard step. The fix is two operators in the Blender we already run. (2) **Caricature is a per-band axis scale, not anatomy-aware.** `proportion_pass.py` reads only `profile["bands"]` and `profile["head"]`; the `hands` and `boots` keys in `content/design/proportions.json:16-17,29-30` are read by **no code** (verified: `git grep '"hands"' -- tools/ crates/ content/` → 0), and the mitten hand is hardcoded at `proportion_pass.py:138-140` (0.70/1.70/1.40). MakeHuman/MPFB2 — the tool we already call — ships a **named proportion axis** (`proportions` 0..1, blending `idealproportions`↔`uncommonproportions` target stacks) that we never pass. (3) **No face is painted anywhere.** `prop_gen.py` has a helm "brow" and `style_cook.py` bakes palette + AO + light, but no pass draws eyes/brows/mouth; the 2005 look needs the face as a *painted region of one atlas*, and the PS1-era CC0 pack shows exactly that layout. (4) **The light is painted into vertex colours only.** The 2005 prop look put the light in the **texture** — one vertical gradient ramp per material, so the prop reads without a light rig; that is the single cheapest visual win left, and KayKit's CC0 atlas shows it. New donors, none previously mined: `cool-japan/oxihuman` (Apache-2.0 code, CC0 body data, Rust, <https://github.com/cool-japan/oxihuman>), `mikedh/trimesh` (MIT, <https://github.com/mikedh/trimesh>), `amPerl/nif` (MIT, <https://github.com/amPerl/nif>), `Mesh2Motion/mesh2motion-assets` (CC0, <https://github.com/Mesh2Motion/mesh2motion-assets>), `KayKit-Game-Assets` (CC0, <https://github.com/KayKit-Game-Assets/KayKit-Character-Pack-Adventures-1.0>), `makehumancommunity/makehuman` (CC0 assets, <https://github.com/makehumancommunity/makehuman>), and `wjakob/instant-meshes` (BSD-3, <https://github.com/wjakob/instant-meshes>, only as a correction to an existing LADDER card).

## Rejections

Checked and dropped, one line each, so nobody re-mines them:

- **`wjakob/instant-meshes`** (BSD-3-Clause, `LICENSE.txt` read live 2026-10-21, <https://github.com/wjakob/instant-meshes/blob/master/LICENSE.txt>) — field-aligned remeshing, `src/field.cpp`, `src/extract.cpp`. Same gap as the open LADDER QuadriFlow card; a second donor, not a new row.
- **`huxingyi/autoremesher`** (MIT, `LICENSE` read live, <https://github.com/huxingyi/autoremesher/blob/master/LICENSE>) — quad remesher over Geogram + libigl + isotropicremesher; a Qt/TBB desktop application, not a library we can call headless. Duplicates the same LADDER card.
- **`Mesh2Motion/mesh2motion-app`** (<https://github.com/Mesh2Motion/mesh2motion-app>) — imports a GLB, fits a skeleton inside it, exports animations; exactly the "import a model, give it a rig" flow. **No LICENSE file at the repo root** (contents API: path does not exist) and `package.json` says `"private": true` → no grant. Ideas only, no bytes.
- **`dicebear/dicebear`** (MIT, `LICENSE` read live, <https://github.com/dicebear/dicebear/blob/main/LICENSE>) — deterministic seeded SVG avatars, 63 styles, with a Rust port under `src/rust/core`. Right shape for "a seed always gives the same face", wrong shape for the job: it emits flat 2D SVG, not marks painted into a 3D head's atlas region. Its determinism idea is worth stealing inside row 4.
- **`makehumancommunity/makehuman`** as a *code* donor — `makehuman/core/transformations.py` is AGPL-3 ("Licensing: AGPL3" in its own header, <https://github.com/makehumancommunity/makehuman/blob/main/makehuman/core/transformations.py>). Assets are CC0 (`LICENSE.ASSETS.md`, <https://github.com/makehumancommunity/makehuman/blob/main/LICENSE.ASSETS.md>) and that is what we use; the code we do not.
- **`makehumancommunity/mpfb2`** as a *code* donor — GPL-3.0 (`LICENSE.CODE.md` read live, <https://github.com/makehumancommunity/mpfb2/blob/main/LICENSE.CODE.md>). We invoke it as an installed Blender extension (the posture `content/design/asset-pipeline.md:149-159` already sets); we do not port its code.
- **MakeHuman `data/skins/default.mhmat` and `data/eyes/`, `data/eyebrows/`** (<https://github.com/makehumancommunity/makehuman/tree/main/makehuman/data>) — real skins and eyes exist upstream, but a realistic skin texture is the opposite of the 2005 look. Not a donor.

- **`blender/blender` `source/blender/editors/object/object_remesh.cc`** (<https://github.com/blender/blender/blob/main/source/blender/editors/object/object_remesh.cc>) — Blender's remesh operator (GPL); the retopo row belongs to QuadriFlow, not to a vendored operator.
