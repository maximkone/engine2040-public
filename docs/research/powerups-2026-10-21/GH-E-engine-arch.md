# GH-E: engine architecture donors (read-only research, 2026-10-21)

Short answer: the big architectural donors are mostly mined already or claimed by board rows, so what is
left is narrow and concrete. The ECS question is closed: our world is a fixed spine of five SoA columns
(`crates/ecs/src/spine.rs:1-2`, OBSERVED), so archetype, sparse-set and entity-reuse designs buy nothing.
The job system is in the tree (a loom-modelled pool, fixed chunks, an ordered merge, `crates/ecs/src/pool.rs:1-25`,
OBSERVED) and the save system is in the tree (versioned envelope, CRC, 16 slots, atomic write,
`crates/save/src/lib.rs:1-15`, OBSERVED). What is actually missing is: (1) a stage builder that lets
systems of one tick phase that do not conflict run together and that refuses a cycle in the order edges
(donor: `amethyst/shred`); (2) a per-tick rewind-and-reexecute hash check, so every tick is proved
recomputable from its own state (donor: `pond3r/ggpo` synctest); (3) the netcode model in writing, so
the owner can choose server-authoritative or rollback (donor: the same GGPO guide, with RetroArch's
lockstep as the second reading); (4) OS push file events behind the seam our own watcher already names
(donor: `notify-rs/notify`); (5) a content manifest that says which output came from which input, a
cooked-glTF gate, and a checked reader so a damaged bundle is an error and not a panic (donors:
`treeverse/dvc`, `KhronosGroup/glTF-Validator`, `google/zerocopy`). Every donor below was read live on
2026-10-21 through the GitHub contents API; licences were read live too, and no donor bytes are vendored.

- `rust-lang/rust` `compiler/rustc_task_graph/src/core.rs` — 404s today on both `main` and `master` (contents API and raw.githubusercontent, read 2026-10-21); the crate is not in this repo's `compiler/` tree. `compiler/rustc_thread_pool` exists but its README says it is a rayon-core fork, and rayon is already claimed by PW20 (`docs/SPRINT-28-powerups.md:131`).
- `rayon-rs/rayon` — already the named donor of PW20; nothing left to read for this lane.
- `crossbeam-rs/crossbeam` `crossbeam-deque/src/deque.rs` (MIT OR Apache-2.0, read 2026-10-21) — the work-stealing deque needs lock-free unsafe code, and the workspace denies unsafe (`Cargo.toml:49`); a mutex-per-worker copy only moves the contention of our single shared queue (`crates/ecs/src/pool.rs:1-25`). Dies on the no-unsafe rule, not on the idea.
- `uxlfoundation/oneTBB` (Apache-2.0, read 2026-10-21; `LICENSE` path 404s, the API license field says Apache-2.0) — `include/oneapi/tbb/partitioner.h` offers `auto_partitioner`, `simple_partitioner`, `static_partitioner`; we already have fixed chunking (`crates/ecs/src/jobs.rs` `ChunkSize`) and an ordered merge, so a partitioner adds nothing.
- `smol-rs/async-task` (Apache-2.0 per API, read 2026-10-21) — "the job system owns the queue, the app owns the policy" is already how `crates/ecs/src/pool.rs` works.
- `amethyst/amethyst`, `leudz/shipyard` (MIT OR Apache-2.0, root LICENSE files read 2026-10-21), `Indra-db/Flecs-Rust` (MIT per API) — full ECS rewrites; our spine is fixed columns, so they die like EnTT (GH-E10). `amethyst/shred` is the only useful piece of that family, and it is GH-E1.
