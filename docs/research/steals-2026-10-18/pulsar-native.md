2. Latent calls with one suspend mechanism and one ask | Far-Beyond-Pulsar/Pulsar-Native@main:crates/core/pulsar_script_vm/src/latent.rs:1-22,29-49 (read 2026-10-18) | MIT | SIM (scheduling) | lands crates/ai (embedded seam) and the door's staged actions | S
   Idea: the VM has exactly one way to suspend a call (the `Wait` instruction parks the frames in a `Continuation`) and exactly one way a native asks for it (write a `Wake` into the `Latent` state, and the VM suspends right after the native returns). `Wake` is one of `Frames(u32)` (at least one -- a call never resumes on the tick it suspended in), `Until { predicate }` (a named parameterless bool function tested once per tick before tick runs), or `Event { name }`. Timers are plain data per instance: `Timer { handle, key, function, remaining, repeat }`, where setting the same `key` again restarts the countdown instead of adding a timer, and a fired timer names an exported function the runtime calls (so a callback can itself wait and set timers). `Latent::advance` is the runtime's, not the VM's: the VM owns no clock.
   Maps: our door and AI seam already submit validated actions, and a staged action needs exactly this: "do this in N ticks" / "until this is true" / "when this event arrives", with the tick loop owning the clock and no clock inside the action. The `Frames(>=1)` rule is the same one-tick-atomicity rule our fixed tick wants.
   Moves: staged actions get three named forms instead of ad hoc counters; a timer key makes retrigger explicit. Unmeasured.
   Proof: cargo test -p engine-ai --lib latent x2 (Frames(1) fires exactly one tick later; Until predicate is tested before tick not after; the same key restarts rather than doubles; no clock is read inside the seam).
   Risk: a per-tick predicate is a cost every tick. Kill: if predicates cost more than 0.05 ms a tick in the arena, keep Frames and Event and drop Until.

3. Warm a task pool before any allocation is measured | Far-Beyond-Pulsar/Pulsar-Native@main:docs/task-pool-startup-validation.md:11-19 (read 2026-10-18) | MIT | SIM-adjacent (startup, test honesty) | lands crates/perf counting-allocator tests and worker startup | S
   Idea: a documented startup fix with the numbers to back it. A heap test saw +960 bytes / +3 blocks idle in all 12 isolated runs; executing a task before sampling made all 12 windows flat; the cause was that `TaskPool::new` returned before a worker entered its executor, so thread-local and queue initialization landed after the observation began. The fix: the constructor waits for each worker to enter the executor and poll it once. After the change the original probe reported zero extra bytes in 12 runs, and the fix is stated as startup synchronization only -- it does not change scheduling, the idle yield, or shutdown.
   Maps: this is the shape our alloc-probe tests want. Our arena/perf tests assert allocation counts; a pool or a lazy thread that warms after the first sample makes them flaky or, worse, hides real growth. "Warm, then measure" is a one-line rule for the counting-allocator tests (crates/core/src/alloc_probe.rs, crates/perf).
   Moves: alloc tests start from a warm pool; an idle-growth red becomes trustworthy. Unmeasured until we have such a pool.
   Proof: a report that re-runs any allocation test that failed in an earlier run with the pool warmed first, and the same test green 12 times.
   Risk: a constructor that blocks on every worker can stall startup. Kill: if warm-up adds more than 20 ms to a fresh launch (startup budget, runtime.md), warm lazily at the first tick instead.

4. Host-attached profiler so a plugin's spans land in the editor's trace | Far-Beyond-Pulsar/Pulsar-Native@main:crates/profiling/src/scope.rs:13-40,42-50 (read 2026-10-18) | MIT | PRESENTATION (tooling) | lands crates/perf/src/profiler.rs and the editor flamegraph | M

   Maps: our profiler already has named spans (profiler.rs:281 `system_span`) and an on/off switch (:52).    Moves: spans from a second process/binary land in one trace instead of two; a scope id stays unique across the boundary. Unmeasured.
   Proof: a test that attaches a fake host and asserts the guest's `allocate_scope_id` increments the host's counter (x2), plus one merged trace from two binaries with no duplicate scope ids.
