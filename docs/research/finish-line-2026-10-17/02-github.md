New facts since the earlier research (all 2026):
- Box3D (Erin Catto) was released in June 2026. A pure-Rust port is bit-exact with the C code. A fixed-point fork also exists.
- Rapier 0.36 (2026-09-25) added soft bodies (shape matching, springs, FEM, joints on soft bodies, tearing, skinning). The engine is already on 0.36.
- Bevy 0.19 (2026-06-19) and 0.20 (2026-10-08) shipped. 0.20 made WESL its shader language, added mesh shaders, a GPU texture-compression backend (`ctt`) and a seeded schedule shuffle.
- wgpu 30.0.1 added `InstanceFlags::STRICT_WEBGPU_COMPLIANCE`. Chrome 149-150 shipped WebGPU "immediates" (push constants). Chrome 144 made `writeBuffer`/`writeTexture` faster.
- WebTransport and a WebSocket fallback now share one Rust trait (`moq-dev/web-transport`, `qmux`).

## Why the top items are on top

1. **box3d-rust.** It is the only open code found that is both a pure-Rust 3D physics engine with ragdoll joints and a stated bit-exact match to a C reference with a determinism test suite and recording/replay. It answers the open web question (WEB3: does physics match on wasm?) with a test someone else already wrote. Box3D itself is v0.1 and young (released June 2026). Check the port's claim by running its `determinism_tests.rs` on Windows and wasm before any board row relies on it.
2. **web-transport.** WEB9 needs a browser client, a server and a fallback. This one library family shape-matches our Quinn code and keeps the codec bytes identical on both paths.
3. **Strict WebGPU flag.** One flag in CI turns "works on my GPU" into a test of the web feature set.
4. **ssimulacra2.** Pure Rust and small. The golden flow lost its metric when the look subtree was cut.
5. **fixed3d.** It shows what a fully integer 3D solver costs (about 2.2x on one Apple chip, scalar). That number sets the budget for an integer ragdoll solver. Read first, port later.

## Traps and honest limits

- **box3d-rust** is serial and scalar by design. 19 stars, one author. The README's "bit-exact vs C" is a claim I did not reproduce. Box3D's own C determinism covers its scalar and SIMD paths; the port only follows the scalar path.
- **fixed3d** timings are one Apple M3 Ultra, macOS, Clang. No MSVC or wasm numbers. Its credit request is a courtesy, not a license term. It is a fork that merges upstream, so file layout may shift.
- **Rapier soft bodies** are float and new (first release). Use them in physfx only. The soft-body shape matching donor in our `destruction/shape_match.rs` already follows Rapier's older file.
- **wgpu compatibility mode** (Chrome 146 ships it on GLES 3.1) is NOT implemented in wgpu (changelog says "see #8124"). It is not a potato-tier path for us yet.
- **Mesh shaders** (wgpu 28+, Bevy 0.20) are native only. WebGPU has no mesh shaders. Do not plan a web meshlet path on them.
- **meshoptimizer-rs** has 0 stars and a copied MIT license file that GitHub could not classify. `meshopt-rs` (yzsolt) has no wasm support yet.
- **Closed or idea-only:** ZeroMind/OrigoZero (hosted, proprietary; shows the market, no code), SpawnForge (source-available, NOASSERTION), Ziva playtest agent (paid, hosted model), Framesmith (no license), La Forge (license unread), ALICE-Physics (AGPL-3.0: do not copy), loom-engine and amoris (1 and 5 stars, very early).
- **Not read in full:** Bevy 0.20 sections other than WESL, mesh shaders, schedule shuffle, panics and texture compression; Nexus and Khal source; Hearth `docs/tester.md` (only the README); the Unity "Search -> Execute -> Verify" Reddit post (page did not load).
- Search quota: GitHub unauthenticated search rate-limited once; I switched to `gh api` (read-only) for the rest.
