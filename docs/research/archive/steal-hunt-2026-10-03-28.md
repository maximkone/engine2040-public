## CARD 1 — ember-spotting + contact fire spread over the bonded graph, integer-only

- Source: `CIMAFoundation/propagator_sim@48b45078093692aa8dcca98f51849a5fbcd981a5`
  (default-branch HEAD at read) — `docs/spotting.md` (SHA `10ab8b36ad655a6457883011bc98095fbb1a29d6`,
  read live 2026-10-03 via GitHub API) + `LICENSE.md` (SHA `4153cd377537ff81e00f8a6453dc278600f4ef2b`).
  Donor is wildfire science (outside engines/games). Updated 2026-09-01; has `tests/`,
  `benchmarks/`, `example/example_spotting_dynamics.py` (listed, not read — no claim).
- License: EUPL-1.2 (copyleft, NOT on the allow-list) — ideas only, reimplement
  std-only integer, zero bytes vendored, never a dependency.
- What it does (their words, condensed): 3-state CA (unburned/burning/burnt) driven by
  (a) contact contagion plus (b) ember spotting: a burning spotting-prone cell emits a
  Poisson-distributed ember count (mean `LAMBDA_SPOTTING`); each ember lands at a
  lognormal distance with median `d ∝ U · I^(1/3)` (linear in wind `U`, cube-root in
  fireline intensity `I`), concentrated downwind by a wind-independent anisotropy
  constant; sub-`2·cellsize` throws are filtered back to ordinary contact spread;
  landing ignites with probability `P_c = P_C0 · (1 + prob_ign_by_embers)` after a
  lognormal delay before the spot fire can propagate. Per-fuel flags: `spotting: true`
  plus `prob_ign_by_embers`; a master `do_spotting` switch gates everything. Their
  own postmortem (kept): the earlier Alexandridis-style formula had a wind-independent
  ~100 m base and sprayed embers isotropically at 0.1 km/h — the fix put wind
  dependence in the distance *magnitude*, which is why light-wind spotting vanishes.
- HOW THEY HANDLE it (data shape / order / cuts / what broke): per-cell fuel rows +
  per-realization probability fields (`spotting_generation_probability`,
  `spotting_receiving_probability`) separating contact vs ember spread; order is
  contact step, then ember launch/transport/land/ignite-delay; they test via
  realizations + GeoTIFF snapshots + example scenario; what broke is documented
  above (isotropic low-wind spray) and fixed by construction, not tuning.
- Home (existing files): `crates/destruction/src/spread.rs` (integer Q16 flood beside
  the crack-strain pass) + `crates/destruction/src/material.rs` (`burn_q16` rows feed
  fuel units; `is_combustible` gates ignition). No new crate, no `fire.rs` alone.
- Fixes: BX Tier B "fire spreads by material" (`docs/plan/body-and-break.md` §2 Tier B);
  moves FOCUS Core proof 2 (Bodies: same hash on every PC and in replay, BX28).
- Net lines: ~120 (integer fuel-ledger + contact pass + seeded-ember pass, Q16/U fixed).
- Proof: NOT RUN. Proposed spike: 8-chunk timber/thatch wall fixture, seeded ignition,
  `do_spotting` on/off; metrics: burnt set equality x2, contact-vs-ember split counters,
  digest x2, step µs. Engine evidence actually in hand: fuel rows + missing sim (above).
- Kill: any float or wall-clock in hashed state; any digest drift x2; ember pass over
  the 0.15 ms/cut slice; light-wind ember throw (the donor's own bug shape) — replays

## CARD 2 — pancake cascade before the orphan flood (gravity pass, then flood-fill)

- Source: https://www.monsterdestruction.com/blog/building-destructible-voxel-city-browser/
  (devlog, published 2026-07-10, read live 2026-10-03 via webfetch; game blog,
  outside this repo's donor set). Corroborated shape (not vendored): Kronnect Voxel
  Play structural-collapse docs (connectivity graph vs ground/anchored support) and the
  Unity/Roblox forum threads on flood-fill structural integrity (search snippets only).
- License: n/a (blog prose, ideas only — no code taken, nothing to vendor).
- What it does (their words, condensed): two systems compose in order. (1) Gravity
  pass: each layer's *remaining structural strength* is compared against the *load of
  everything stacked above it*; a weakened floor fails and the floors above come down
  onto the next, which must hold more with less — pancake collapse emerging from the
  support model, so hollowing the ground floor beats punching top-down. (2) Flood-fill
  from the ground through remaining voxels catches whatever got orphaned in the chaos
  and detaches it as falling debris. Supporting discipline: ONE damage primitive for
  every weapon (`damageSphere`: position, radius, force — one hot loop, trivially
  extensible); hollow shells with floor slabs + core (90% of "real building" feel for
  a fraction of voxels); pooled debris — zero allocation mid-combat (steady frame
  times over peak frame rate).
- HOW THEY HANDLE it: strength-vs-load per layer evaluated top-down, then
  connectivity flood; damage unified to a single sphere call; interiors faked with
  slabs+core; effects pre-pooled. What they cut: solid interiors, per-weapon code
  paths, GC-touching combat allocation.
- Home (existing files): `crates/destruction/src/bonded.rs` (`refresh_support` :549
  + `step` :376 hunks — layer cascade evaluated before the binary orphan flood) +
  `crates/destruction/src/budget.rs` (per-event caps ledger already pools/caps debris).
- Fixes: BX13 collapse ordering (binary flood frees a severed top as one island same
  tick; no progressive pancake) + BX24 `hit.simulate` (single damage primitive shape).
  Moves FOCUS Core proof 2 (Bodies) toward the 400-element load-path bar.
- Net lines: ~60 (per-layer strength/load pass in canonical order + cascade receipt;
  damage-sphere verb is a thin mapper over `apply_impact`).
- Proof: NOT RUN. Proposed spike: 3-story 400-element fixture, ground-floor vs
  top-floor severing; metrics: top-down failure order matches hand oracle, final free
  set equality, digest x2, step p95. Engine evidence in hand: binary flood + zero-alloc
  refresh tests (above); donor evidence: full article text (this file's source).
- Kill: final free set differs from binary-flood oracle; any digest drift x2; step p95
  over budget; any float in hashed bytes; cascade that a single bond-break cannot
  explain (no animation-shaped outcomes in the tick).
- Effort/risk: S-M / low. Risk is duplicating the ACCEPTED GNS load-leg — this is
  scoped as its ordering consumer (loads already valued; this card sequences failure),
  never a second load model.
- Plan prefix: BX (BX13 collapse-order detail). Core line: Bodies — collapse by load
  path, identical x2 and across rollback.
