## CARD 1 — PD-torque drive law: D-term + magnitude clamp + degenerate-dt guard

- Source: `bhubbard/active-ragdoll-rs@a2fc2f1ad8c08590c4571d5b731ac478f1a29e78`
  (pinned ref from the live read; created 2026-09-26, 0 stars — judged by code/tests
  per packet, not stars) — `src/pd.rs` (`PdController3d::calculate`,
  `PdController3d::clamp_magnitude`; port of Unity Humanoid ActiveRagdoll PD, stated
  in-file) + `tests/pd_tests.rs` + `tests/accuracy_test.rs` + `BENCHMARKS.md`
  (all listed live 2026-10-03 via GitHub API; `src/` 16 files, `tests/` 18 files).
  Rust, `rapier3d` optional behind `rapier3d` feature (`Cargo.toml`, `glam`-only core).
- License: MIT OR Apache-2.0 — verified live 2026-10-03 three ways: `Cargo.toml`
  `license = "MIT OR Apache-2.0"` (file read live), plus `LICENSE-MIT` +
  `LICENSE-APACHE` files listed at root. Adaptable with attribution + `PORT()` marker.
- What it does (their shape, condensed): per-joint PD servo on the pose error vector:
  `derivative = (error - last_error) / dt; signal = P * (error + D * derivative)`.
  Three disciplines ours lacks: (1) the D-term itself (velocity-error damping — ours is
  P-only velocity set); (2) a magnitude clamp on the output torque vector
  (`clamp(v, max)` by `length_squared` compare, no `sqrt` on the hot path unless
  clamping); (3) a degenerate-step guard — `dt <= 0` or non-finite returns the P-term
  only and records `last_error`, so a paused/odd step can never NaN or spike. Unit
  proof in-repo: proportional-step exact (`8.0*(1.0+0.01*50.0)=12.0`), steady-state
  (second identical error -> derivative 0 -> pure P), clamp (5.0 -> 2.5 direction-kept,
  small vector untouched).
- HOW THEY HANDLE it (data shape / order / cuts / what broke): state is two gains +
  one `last_error` vector per controller (1D scalar twin included); order is
  error -> finite-difference derivative -> P*(err + D*deriv) -> clamp; they cut the
  integral term entirely (PD, never PID — no windup state, replay-friendlier); the
  dt-guard is their "what broke" fix (division by zero / non-finite dt). Master/slave
  split (`src/master.rs`, `src/controller.rs` listed, not read — no claim) keeps the
  animated target (master) separate from the physics follower (slave). What they do
  NOT handle (our edge): determinism across PCs — their math is `f32`/`glam` with no
  hash law; the steal is the *law shape* reimplemented in our deterministic integer/
  fixed discipline, never their float bytes.
- Home (existing files): `crates/physics/src/powered.rs` (`DriveParams` hunk: add
  `damping_gain` + output clamp beside `max_speed`/`max_spin`; degenerate-dt guard in
  the step glue) — reimplement std-only, deterministic, with attribution. No new crate.
- Fixes: PX1 drive quality (oscillation/settle of the powered servo) + BX4 (severed-limb
  chain held aloft by the same servo) + BX5 (injured-locomotion stability). Moves FOCUS
  Core proof 2 (Bodies: ragdoll identical on every PC and in replay, BX28).
- Net lines: ~80 (D-term + clamp + guard + 3 unit tests mirroring their three).
- Proof: NOT RUN. Proposed spike: fallen-chain recovery fixture, P-only servo vs
  PD servo at matched P; metrics: settle ticks, overshoot permille, step cost, digest
  x2 + shuffled-insertion order proof. Donor evidence in hand: the three unit tests +
  file listing above (mechanism read live, not copied).
- Kill: settle-tick improvement < 15% at matched overshoot; any digest drift x2; any
  float/transcendental in hashed bytes; step cost over the 0.15 ms/cut slice; any
  NaN/Inf in a degenerate-dt probe (their guard must hold in our port).
- Effort/risk: S / low. Risk is float creep into the tick — the card mandates the
  deterministic port (fixed/Q16 or integerized gains) with the hash gate as the proof.
- Plan prefix: BX (PX1 drive-law detail, Tier A body chain). Core line: Bodies —
  deterministic ragdoll, one hash at every setting.

## CARD 2 — cannonball knock-down rig: reduced-mass impulse + one-shot projectile fixture

- Source: same donor + pinned ref as CARD 1 — `src/projectile.rs`
  (`Projectile::shoot`, `Projectile::step`, `Projectile::check_sphere_collision`;
  port of Unity `ShootObject.cs`, stated in-file) + `tests/projectile_tests.rs`
  (shoot-pose exact, hit-impulse-some + one-shot deactivate).
- License: MIT OR Apache-2.0 (same triple verification as CARD 1).
- What it does (their shape, condensed): deterministic ballistic test rig for
  knock-down: spawn `position = origin + forward * 1.5`, `velocity = forward * speed`
  (default 21.0 m/s, r = 0.15 m, m = 4.0 kg cannonball); gravity Euler step with
  lifetime; auto-deactivate underground (`y < -5`) or stale (`lifetime > 10 s`);
  sphere-collision returns a closed-form elastic impulse `J = 1.6 * m_eff * v_rel`
  with `m_eff = (m_proj * m_target) / (m_proj + m_target)`, one-shot (deactivates on
  hit so a projectile can never double-count). Tests pin spawn numbers exactly and
  the hit/no-double-hit behavior.
- HOW THEY HANDLE it: data is position/velocity/radius/mass/active/lifetime (plain
  struct, `Copy`); order is shoot -> step (gravity) -> sphere-check (impulse or
  nothing); they cut continuous collision (single sphere check per step) and
  multi-hit (one-shot); the `1.6` restitution-mass factor is their tuning constant,
  exposed, not buried. Gap vs us: our `hit_react` bounds impulse (`IMPULSE_Q8_MAX`)
  and our servo takes impulses (`NonFiniteImpulse` guard) but no fixture maps
  projectile energy -> balance-escalation tier with numbers.
- Home (existing files): `crates/physics/tests/ragdoll_tape.rs` (seeded
  cannonball-vs-fighter tape beside the rerun-x2 harness) + threshold table in
  `crates/physics/src/balance.rs` (push / stumble / arm-catch / full-ragdoll tiers
  calibrated by the tape). Feeds `hit.simulate` (BX24) and BreakBench (BX25) later.
- Fixes: BX5/BX6 calibration ("which blows escalate" is currently tabled by judgment;
  this makes it measured) + BX28 corpus (adds ballistic knock-down tapes). Moves FOCUS
  Core proof 2 toward replay-exact bodies.
- Net lines: ~70 (projectile struct + step + impulse fn in fixed/integer form + tape
  test with 3 tiers pinned).
- Proof: NOT RUN. Proposed spike: 4 kg @ 21 m/s vs 70 kg fighter fixture, seeded;
  metrics: impulse permille table, tier reached (push/stumble/fall) equality x2,
  digest x2, no double-hit (projectile inactive after first contact). Donor evidence
  in hand: spawn/impulse/one-shot tests listed + mechanism read live.
- Kill: tier mapping differs run-to-run (any nondeterminism); any digest drift x2;
  restitution constant tuned per-fixture instead of one global (no hidden knobs);
  tape cost over budget; dupe — if the spike finds an existing energy-tier fixture
  in `balance.rs` tests, this card dies and becomes a LADDER dupe line.
- Effort/risk: S / low. Risk is scope creep into ballistics game-feel (BX20 siege
  table owns damage; this card is knock-down tiers only).
- Plan prefix: BX (BX5/BX6 calibration leg, Tier A). Core line: Bodies — same hash on
  every PC and in replay.
