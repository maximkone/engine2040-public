## HOW THEY HANDLE it (mechanism notes)

- Tickwise observer shape (from `probe.rs`, pinned behavior): ONE trait, three callbacks, FFI-clean (no generics/closures): `light_hash() -> u64` (desync-critical digest ONLY - entity counts, RNG seed, score - budget target <1% of tick), `full_hash() -> u64` (ALL gameplay state, every N ticks; anything omitted is a blind spot), `state_dump() -> StateDump` (full structural dump, dump-ticks only, allowed to be expensive). Two refusal rules: `hash_algo_id()` (recorder refuses a header claiming another algo instead of writing a mislabelled recording) + `last_error()` (probe reports observation failure; recorder/replayer REFUSES the tick instead of storing a hash describing nothing). `probe_is_dyn_compatible` test pins trait-object safety (the FFI contract).
- Tickwise two-pass workflow (from README): PASS 1 always-on cheap (`a.rec`/`b.rec` = inputs + per-tick hashes; `tickwise compare` names first divergent tick + hash kind: "light-hash mismatch, confirmed by full hash at tick 4200"); PASS 2 targeted (`dump_at_tick = 4021` replay both sides; `tickwise diff` reports `players[2].velocity.x A: 3.5 B: 3.5000001 (sub-epsilon float drift)` vs `projectiles.len A: 14 B: 15 (structural)`). Replay-free escape hatch: `dump_interval` stores full dumps inside `.rec`, `diff a.rec b.rec --at <tick>` reaches field level with NO replay (opt-in: costs a full state walk every N ticks). Self-check entry: record once, replay inputs, `compare original.rec replayed.rec` - anything but identical means the sim is not deterministic (found before players do). Exit codes follow `diff` (0/1/2) so CI branches on the verdict. Numbers claimed: recorder 20 ns/tick; core `#![forbid(unsafe_code)]` (unsafe only in `tickwise-ffi`, each block SAFETY-commented, clippy-enforced). What they cut: no transport/netcode/rollback engine, no fixed-point lib, no GUI, no async/tokio, no auto-probes on Unity/Unreal/cocos (you name the fields - same discipline as our cards).
- Klotho determinism shape (from README + Docs map): sim core is pure engine-agnostic C# (no engine refs), FP64 32.32 ONLY + Xorshift128+, `Frame` = single byte[] heap, `FrameRingBuffer` snapshots, Verified chain (all real inputs known, immutable) vs Predicted chain (guessed remote input, provisional; rollback restores snapshot + re-simulates), graded recovery ladder (hash check -> rollback -> full-state resync -> corrective reset), build-time `DeterminismAnalyzer` (flags float/non-deterministic APIs IN SIM CODE), `SyncTestRunner` + `DeterminismVerificationRunner`, `Diagnostics/` fault injection.
