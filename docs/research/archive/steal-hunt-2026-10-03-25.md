## Card 3: negation-symmetric fixed mul + always-saturate overflow with a zero-asserted counter

- Source: `PORT(renew-engine/renew@91ba7053:crates/fixed/README.md)` (blob `edc0b84e`, full text read live

  License: Apache-2.0 (blob `d6456956`, full text read live 2026-10-03) — allow-listed, adapt with attribution.
- What it does: `Q47.16` in `i64` for sim code that must reproduce bit-for-bit, with four measured rules:
  (a) 16 fractional bits BECAUSE physics squares things — squarable-range table (±1.2e7 vs Q32.32's ±4.6e4,
  256x working room); (b) NO float in any signature + float-closure rule with TWO questions — deny
  `clippy::float_arithmetic` (operators) AND ban float methods by name in `clippy.toml` (they measured
  `mul_add` rounding differing by target/lowering; `tests/angles.rs` records a sine reference that passed on
  one machine and failed on another); (c) mul rounds-to-nearest ties-away-from-zero, NOT shift — the obvious
  `(a*b)>>16` is asymmetric under negation (`(-a)*b` vs `-((a*b))` differ), deterministic yet wrong for
  physics (left-moving vs right-moving bodies accumulate different error); property-tested, fails against the
  shift, verified by swapping one in; (d) overflow SATURATES in every profile + thread-local `saturations()`
  counter asserted zero the way a frame loop asserts allocations; binary-angle `u32` (full turn = 2^32, wrap
  exact forever); 513-entry sin table, measured worst error 1.0322 ulp.
- HOW THEY HANDLE it: integers only in sim closure (`renew-math` floats physically unreachable); `from_int`/
  `from_ratio` (9.81 = `from_ratio(981,100)`, no float ever exists)/`from_bits` all `const fn`; exact
  `perpendicular` (swap+negate) kept separate from rounding `rotate`; fallible `normalize`; generated (not
  hand-written) table with an entry-vs-reference test — the ONLY float use in the crate's world.
- Home (existing file): `crates/core/src/fixed.rs:75-78` — our `Fixed` is also Q47.16 (convergent choice,

  2026-10-03: `crates/core/clippy.toml:13-27`), so the closure half EXISTS — the rounding + saturation halves
  do not (wrapping, not saturating; no symmetry property test; no saturation counter).
- Fixes: Bodies determinism axis — left/right-symmetric error accumulation + profile-independent overflow for
