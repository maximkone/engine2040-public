# Receipt: OPT61, SIMD128 in the shipped wasm (2026-10-24)

The web build shipped scalar wasm while `docs/HASH-LAW.md` already recorded
`wasm32-wasip1-simd128` as MATCH. This receipt names what changed, the bytes and
the browser proof. It moves no hash: the page's golden line still reads
`d57b5c8ae3096614`.

## What changed

| path | before | after |
|---|---|---|
| `tools/web-build.mjs` | wasm-opt features ended at `--enable-mutable-globals` | adds `--enable-simd`; the cargo build gets `CARGO_TARGET_WASM32_UNKNOWN_UNKNOWN_RUSTFLAGS="-C target-feature=+simd128"` |
| `tools/web-build.test.mjs` | no SIMD assertion | pins the flag in the passed list and that the rustflags env is target-scoped, never global |

Two details worth the ink:

- The binaryen 133 flag is `--enable-simd`. `--enable-simd128` is rejected by
  `wasm-opt` ("unknown option"), so a copy of the rustc spelling fails the build.
- The rustc flag rides on `CARGO_TARGET_WASM32_UNKNOWN_UNKNOWN_RUSTFLAGS`, not
  `RUSTFLAGS`: the latter would also hit the host build of build scripts and
  proc macros in the same invocation.

### One probe failed, and why it is not the build

The run exits 1 on the memory probe:

```
MEMORY FAILED pages 235 -> 251 after a forced grow of 16; peak 251 pages =
16449536 bytes (+25% = 20561920); readings [178,235,251] - the frame counter
stopped after the memory grew
```

The byte budget passes (16.4 MB against a 20.6 MB ceiling). What failed is
`memoryProbe` in `tools/web-browse.mjs`: it reads the frame counter, waits
1000 ms, and expects it to move. This machine has no hardware WebGPU adapter for
Chrome, so the page runs on SwiftShader and reports
`"frameMs":1158.90` (gtao 149 ms, sky 31 ms per frame). One frame takes
1.16 s, so no frame can arrive inside the 1 s window. The frame counter is not
stuck: the frozen-grow capture, the quota drill, the visibility skip and the
forced device loss all passed on the same page.

The gate stays as it is. On a machine with a hardware adapter the frame rate is
far above 1 fps and the probe can pass; here the software rasterizer sets the
floor. Recorded, not worked around.

## What is proven, and what is not

- Implemented: the flag and the target-scoped rustflags in `tools/web-build.mjs`.
- Compiled: `node --test tools/web-build.test.mjs` green; a real `dist/web` build
  under the size limit.
- Proved in a browser: the golden line, the 600-tick wasm tape, page/node frame
  hash equality, a non-blank browser frame, and `v128` in the shipped module.
- Not proved: a browser run on a hardware WebGPU adapter (this machine offers
  SwiftShader only), so the memory probe's timing check is unproven here.
