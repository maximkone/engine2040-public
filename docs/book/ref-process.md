## 4. Board rows: format and ready rule

Board: `docs/SPRINT.md` is the index. Rows live in `docs/SPRINT-*.md` shards (one per section, listed in `SPRINT.md`). Done rows move to `docs/archive/SPRINT-done-*.md`. Tools read the index plus every shard as one board (`board-slice.mjs`).

Row shape (from `docs/SPRINT-22-web-realism.md`):

```
- [ ] WEB2 build: <one-paragraph description>. Diff: regular. Tier A.
  Size M. Owns <paths>. Accept: <checks>. F2P: <fails before>. P2P: <stays passing>.
  needs: none.
```

- A bullet starts with `- [ ] ID` (open) or `- [x] ID` (ticked). Continuation lines run until a blank line.
- ID: capital letters and digits, optional lower letter (for example `EG8`, `LF10`, `GS16`, `WEB2`).
- `needs:` is last and ends with a period. Every id in `needs:` must be ticked or in the same plan.
- Sizes: S up to 150 changed lines, M up to 400, L is several landings (`SPRINT-22-web-realism.md` header). Plan README says S = 1 session, M = 2 to 4, L = 5 to 10.
- Every NEW row carries `F2P:` (fails before) and `P2P:` (stays passing). Without both it is not ready (`SPRINT.md` "How a row works").
- Acceptance marked "(reference GPU)" needs the RTX 3050 box.

Ready rule (`SPRINT.md`, implemented in `board-slice.mjs` `rowReady`):

1. Open (`[ ]`).
2. Every `needs:` id is ticked.
3. Text has neither `BLOCKED:` nor `LATER:`.
4. Not an operator row.

Take rows from `--focus` first. Only when `--focus` is empty take other ready rows, smallest first. Never invent rows. Red-gate fixes come first.

## 5. Ticking a row

- Tick only after the acceptance passed. Put `Landed <sha7>.` in the row text, then change `[ ]` to `[x]`.
- Example from the board: `... needs: none. Landed 8d83670.` (`SPRINT-22-web-realism.md`, WEB1).
- Note: `AGENTS.md` step 4 says "at the end of its first line". Board rows are multi-line paragraphs, and the landed text sits at the end of the paragraph. Follow the rows as they stand.
- Add a receipt line in `docs/SPRINT-19-receipts.md` (newest first). Earlier receipts are in git history.
- Blocked after a second identical failure: write `BLOCKED:` in the row and one `docs/BLOCKERS.md` row. Never resend the whole change.
- After any board or doc edit run `node tools/workspace-check.mjs` (its board check fails on a missing `needs:` id).

## 6. Commits: by path, shared tree

Rule (`AGENTS.md`, `CLAUDE.md`):

- Commit only your own paths: `git commit -m <msg> -- <paths>`.
- New files: `git add -N <file>` first (intent to add), then commit by path.
- Never `git add -A`.

Shared-file method (when another writer has uncommitted hunks in the same file, or files staged in the real index). Source: the owner's session note `shared-tree-commit` (user memory, not a repo file):

1. Apply your edit to a copy of `git show HEAD:<path>` in a scratch directory.
2. `GIT_INDEX_FILE=<scratch>/idx git read-tree HEAD`.
3. `git hash-object -w --path=<path> <scratch file>` gives the blob.
4. `GIT_INDEX_FILE=<scratch>/idx git update-index --cacheinfo 100644,<blob>,<path>` (or `--add <path>` for a file that is wholly yours).
5. `GIT_INDEX_FILE=<scratch>/idx git commit -F <msgfile>`.
6. Afterwards point the real index at the new blobs with `git update-index --cacheinfo` from `git ls-tree HEAD`, so later commits do not revert you.
7. Resync the real index with a path-limited `git reset -q -- <your paths>`. Never a bare `git reset -q`: it drops other sessions' staged files.
8. Edit the working copy too. Otherwise a later path commit drops your lines.
9. Whole-file `git add` only after `git diff --numstat` shows no foreign hunks.
10. Do not `cargo clippy --fix` on Windows for cfg-gated code without checking it by hand.

Message trailer for commits made from this session: `Co-Authored-By: Claude Haiku 5.5 <noreply@anthropic.com>`.

## 7. Proof: what runs where

Before a commit (`AGENTS.md` "Proof"):

- `node tools/rust-quality.mjs` passes.
- `node tools/workspace-check.mjs` passes after board or doc edits.
- `cargo run -p engine2040 --release` gives the same hash twice when simulation code changed.
- `rustfmt --edition 2021 --check <files>` (never `cargo fmt`).
- Iterate locally with `cargo check -p <crate>` only.
- Every test and clippy proof goes through `node tools/gh-check.mjs` (section 8).
- After `node tools/public-export.mjs --commit --push`, read the mirror CI with `node tools/public-export.mjs --ci`.

Tests live as modules of one binary: `crates/<c>/tests/it/` (a new file is a `mod` line in its `main.rs`). A new top-level `tests/*.rs` fails `workspace-check`.

## 8. Heavy cargo on GitHub

- Owner rule 2026-10-17 (in `CLAUDE.md` and `AGENTS.md`): cargo test, clippy and workspace builds run on GitHub through `tools/gh-check.mjs`.
- Usage:
  - `node tools/gh-check.mjs cargo test -p <crate> --lib <filter>`
  - `node tools/gh-check.mjs cargo clippy -p <crate> --all-targets -- -D warnings`
  - `node tools/gh-check.mjs --wait wip-<id>` (exit 3 prints this line)
- Exit codes: 0 pass, 1 fail, 2 could not run, 3 still running.
- The call returns by itself at 100 s (`--budget`, max 1740). No `timeout` needed.
- Runs locally by itself: GPU, window and Windows-only lines (features `window`, `app`, `ui`, `device`; filters naming gpu, window, wgpu, winit, adapter, vulkan, dx12, win32). A pass with 0 tests reruns on the PC.
- It publishes the working tree (including other writers' uncommitted files) to a throwaway `wip-*` branch of the public mirror. No secrets in the tree.
- Detail: `ref-tools.md` section "gh-check.mjs".

## 11. Golden hash

- Golden: `d57b5c8ae3096614` (`AGENTS.md`). Fixture: seed 2040, 600 ticks, `GOLDEN_600` in `docs/HASH-LAW.md`.
- Moves only with an explicit receipt. Look up `docs/HASH-LAW.md` only when the hash moves.
- Fixture v1 stays frozen. New fixtures expand seeds without aliasing (SplitMix64) under a new fixture version.
- Hash scope IN: canonical entity and component state that affects future ticks, RNG state, timers, queued authoritative events, planner state, accepted external actions, asset and rules version references. OUT: GPU handles and pixels, render interpolation, UI, wall-clock durations, model credentials, transport timing, telemetry.
- Canonical serialization: fixed field order, stable ids, numeric encoding and endianness. No `HashMap` iteration order, pointer addresses or native memory dumps.
- Legacy seeding forces the low bit (`Rng::new(seed | 1)`), so seeds `2k` and `2k+1` simulate the same trajectory. Receipt inequality cannot show two seeds differ. Tests assert trajectories.
- Proof for simulation changes: `cargo run -p engine2040 --release` gives the same hash twice.
- Break corpus: `cargo test -p engine-proof break_corpus` (gate G6).
- Tape format and comparison: `ref-tools.md`, `golden-matrix.mjs`.

## 14. Hooks and local gates

Hooks live in `.git/hooks/` (local, not versioned):

- `pre-commit`: runs `node tools/rust-quality.mjs` on the staged tree. A commit that raises the ratchet is refused unless the same commit stages `tools/rust-quality.baseline.json` (`--accept` or `--tighten`).
- `pre-push`: `git lfs pre-push`, then `cargo deny check licenses`, then `node tools/license-gate.mjs`. Exit 1 on failure.
- `post-checkout`, `post-commit`, `post-merge`: present, not described here.

`tools/secret-gate.mjs` exists but no hook calls it. Run it by hand before a push if you need that scan.

`deny.toml` governs Cargo dependency licences only. Donor code from any source may be ported (`AGENTS.md` rule 4).
